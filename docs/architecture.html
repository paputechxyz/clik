CLIk Architecture

Electron three-context desktop app — a Miller-column GUI over any --help-driven CLI, with every run backed by a real PTY

IPC surface (window.clik)

  • • cli:discover, cli:discover-command → cli:discover:progress
  • • scan:resolve|classify|suggest, dialog:pickBinary
  • • registry:list|add|update|remove|reorder
  • • library:get|save|export|import, clipboard:writeText
  • • pty:open|openShell|kill (invoke), pty:input|resize (send)
  • • shell-env:status|refresh, prefs:get|setDismissedUpdate
  • • Push: pty:event, menu:action, update:status

Process & security model

  • • contextIsolation on, nodeIntegration off — the renderer reaches main only through the preload bridge
  • • Never shell: true; the only spawn sites are --help discovery and shell-env capture, both argv arrays
  • • Runs execute in a PTY, not spawn; closing a tab kills it with SIGHUP
  • • node-pty is native — rebuilt against Electron's ABI and unpacked from the asar
  • • Windows: ConPTY, cmd.exe shell tabs, PATHEXT resolution, .cmd shims via cmd /c

State & data flow

  • • useAppStore holds CLI entries, parsed trees, flag values, run tabs, saved commands and history
  • • Parsed trees are cached in tree-cache.json; Refresh drops the cache and re-parses every command
  • • Library writes through to library.json, upgraded on read by library-migrate.ts
  • • Per-tab output is accumulated in the store and replayed into xterm via computeWriteDelta
  • • Login-shell env is captured once at startup and merged with per-CLI env overrides for every run
